# Diaphone — macOS input method

Type notation in any app; it converts **as you type** — each glyph is committed the moment the
keystroke stream can no longer change it, and only the tiny undecidable tail shows as underlined
text in place. No compose/commit step. Design + streaming proof: `../docs/mac-input.md`.

## Build & install (Command Line Tools are enough — no Xcode)

```
make check     # validate the Swift engine port against the Python CLI (480 cases must pass)
make install   # build, ad-hoc sign, copy to ~/Library/Input Methods
```

Then: **System Settings → Keyboard → Input Sources → Edit… → +** → search **Diaphone** (listed
under English) → add. Pick it in the menu-bar input menu and type — `sjok sewp njawr` should
stream out as `s̩ok sép n̩ár`.

The input menu carries **five modes** — Native · IPA · Hungarian · Mandarin · English (a language
mode IS that language's view; the universal glyphs are the Native mode) — plus two switches:
**Loose input** (HU bare a/e · ZH type-Pinyin · EN the digraphs sh ch zh ng th dh + j y w) and
**Dictionary spelling** (EN: real words, committed per word at the boundary).

## Layout

```
Sources/Engine.swift     engine.json model (generated by `diaphone export-json`)
Sources/Decoder.swift    port of decode.py/render.py — batch conversion
Sources/Streamer.swift   port of stream_poc.py — the incremental committer
Sources/CheckMain.swift  the validation binary (drives Decoder+Streamer from stdin)
Sources/main.swift       IMKServer bootstrap
Sources/DiaphoneInputController.swift   keystrokes → streamer → insertText/setMarkedText
```

The conversion logic is **data + two small ported files**, and neither is trusted by inspection:
`make check` replays the shared corpus through both batch and char-by-char streaming and requires
byte-identical output to `diaphone render`. Run it after ANY change to the engine or the ports.
